1. RINGKASAN EKSEKUTIF (5 Menit untuk Auditor)
================================================================================

CertiPro menggunakan Role-Based Access Control (RBAC) dengan prinsip:

┌─────────────────────────────────────────────────────────────────────────────┐
│                          ARSITEKTUR RBAC                                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│   USER ──→ ROLE ──→ PERMISSIONS ←── MIDDLEWARE ←── ROUTE/ACTION            │
│                                                                              │
│   • User memiliki 1 Role (one-to-one via role_id)                           │
│   • Role adalah grouping, BUKAN authority                                   │
│   • Permission adalah authority sesungguhnya                                 │
│   • Middleware mengecek Permission, BUKAN Role                              │
│   • Controller TIDAK boleh hardcode role                                    │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘

6. MIDDLEWARE IMPLEMENTATION
================================================================================

File: app/Http/Middleware/CheckPermission.php

USAGE:
┌─────────────────────────────────────────────────────────────────────────────┐
│ // Single permission                                                         │
│ Route::get('/asesmen', ...)->middleware('permission:asesmen.view');         │
│                                                                              │
│ // Multiple permissions (OR logic)                                          │
│ Route::post('/asesmen', ...)->middleware('permission:asesmen.submit|asesmen.input');│
│                                                                              │
│ // Controller tidak boleh cek role langsung!                                │
│ // ❌ SALAH: if ($user->role == 'asesor')                                   │
│ // ✅ BENAR: if ($user->hasPermission('asesmen.submit'))                    │
└─────────────────────────────────────────────────────────────────────────────┘

LOGIC FLOW:
1. Middleware menerima permission name
2. Jika user adalah super_admin → BYPASS (allowed)
3. Cek user->hasPermission() melalui role->permissions
4. Jika tidak punya permission → Log ke audit_log + return 403
5. Jika punya permission → Continue request

13. CATATAN AUDIT UI CONSISTENCY (ISO 17024 COMPLIANCE)
================================================================================

PRINSIP KEAMANAN UI-BACKEND CERTIPRO:
────────────────────────────────────────────────────────────────────────────────

CertiPro menerapkan prinsip "Backend = Single Source of Truth" untuk keamanan
akses sistem. UI (User Interface) berfungsi HANYA sebagai refleksi dari 
permission yang tersimpan di database, BUKAN sebagai mekanisme keamanan utama.

ARSITEKTUR KEAMANAN:

14. FITUR RESET PASSWORD (ISO 27001 & ISO 17024 COMPLIANT)
================================================================================

ARSITEKTUR KEAMANAN RESET PASSWORD:
────────────────────────────────────────────────────────────────────────────────

CertiPro menyediakan fitur reset password yang aman untuk semua user dengan
mekanisme self-service (Lupa Password) dan admin-initiated reset.

A. FLOW RESET PASSWORD (SELF-SERVICE):
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. User klik "Lupa Password" di halaman login                               │
│ 2. Input email terdaftar                                                     │
│ 3. Sistem validasi & generate token (hashed, 60 menit expiry)               │
│ 4. Email reset dikirim dengan link unik                                      │
│ 5. User klik link → form password baru                                       │
│ 6. Password baru disimpan (hashed), token invalidated                        │
│ 7. Audit log mencatat seluruh proses                                         │
└─────────────────────────────────────────────────────────────────────────────┘

B. KEAMANAN TOKEN:
- Token tersimpan HASHED di tabel password_resets
- Expiry: 60 menit (configurable via config/auth.php)
- Single-use: Token invalidated setelah dipakai
- Rate limiting: 5 request/menit (route level) + 3 request/jam (service level)

C. ROUTE RESET PASSWORD:
┌─────────────────────────────────────────────────────────────────────────────┐
│ GET  /forgot-password           → Form input email                           │
│ POST /forgot-password           → Kirim email reset (throttle:5,1)           │
│ GET  /reset-password/{token}    → Form password baru                         │
│ POST /reset-password            → Simpan password baru (throttle:5,1)        │
└─────────────────────────────────────────────────────────────────────────────┘

D. AUDIT LOG EVENTS:
┌─────────────────────────────────────────────────────────────────────────────┐
│ password_reset_requested    → User meminta reset password                    │
│ password_reset_email_sent   → Email reset berhasil dikirim                   │
│ password_reset_success      → Password berhasil direset                      │
│ password_reset_failed       → Reset gagal (token invalid/expired)            │
│ password_reset_by_admin     → Admin mengirim reset ke user lain              │
└─────────────────────────────────────────────────────────────────────────────┘

E. EMAIL TEMPLATE (BRANDED):
- Logo LSP (dynamic dari setting)
- Nama LSP (dynamic via systemCompanyName())
- Warna konsisten dengan UI admin (#2563eb primary)
- Tombol CTA "Reset Password"
- Expiry notice (60 menit)
- Footer legal LSP
- Gmail-compatible (table-based, inline CSS)

F. SECURITY CHECKLIST:
✅ Token hashed di database (tidak plain text)
✅ Token kadaluarsa 60 menit
✅ Token single-use (sekali pakai)
✅ Rate limiting di route dan service level
✅ CSRF protection aktif
✅ Generic response untuk mencegah email enumeration
✅ Password complexity enforced (min 8 char, uppercase, lowercase, number)
✅ Audit log lengkap untuk semua event
