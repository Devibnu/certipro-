╔══════════════════════════════════════════════════════════════════════════╗
║                   IDEMPOTENT REGISTRATION FLOW SUMMARY                   ║
║                     1 Pra-Pendaftaran = 1 Pendaftaran                    ║
╚══════════════════════════════════════════════════════════════════════════╝

┌─────────────────────────────────────────────────────────────────────────┐
│ 1️⃣  USER SUBMITS FORM (/daftar)                                          │
└─────────────────────────────────────────────────────────────────────────┘
    
    Input: Nama, Email, No HP, NIK/NIM
           ↓
    [HARD VALIDATION] 
    ├─ Email sudah ada dengan status DITERIMA?
    │  ├─ YES → ❌ TOLAK (redirect + warning message)
    │  └─ NO  → ✅ CREATE pra-pendaftaran (status: BARU)
           ↓
    Redirect: /pendaftaran/sukses
    Output: Nomor pra-pendaftaran (PRA202600123)


┌─────────────────────────────────────────────────────────────────────────┐
│ 2️⃣  ADMIN APPROVES (/adminui/pra-pendaftaran/{id}/status)                │
└─────────────────────────────────────────────────────────────────────────┘
    
    Admin: Status → DITERIMA
           ↓
    [AUTO-CREATE PENDAFTARAN] (PraPendaftaranAdminController)
    ├─ Check: hasPendaftaranSertifikasi()?
    │  ├─ YES → Skip (idempotent, no duplicate)
    │  └─ NO  → Create dengan DB Transaction
    │             ├─ Generate nomor: REG20260001
    │             ├─ Status: DIAJUKAN (not draft)
    │             └─ Link: pra_pendaftaran_id
           ↓
    [SEND EMAIL] (PraPendaftaranDiterima Mailable)
    ├─ SMART LINK LOGIC:
    │  ├─ IF pendaftaran exists:
    │  │  └─ Link: /pendaftaran-sertifikasi/{id}/detail?signature=xxx
    │  └─ IF pendaftaran NOT exists:
    │     └─ Link: /pendaftaran/lanjut/{praPendaftaranId}?signature=xxx
    └─ Security: Signed URL (30 hari expiry)


┌─────────────────────────────────────────────────────────────────────────┐
│ 3️⃣  USER CLICKS EMAIL LINK                                               │
└─────────────────────────────────────────────────────────────────────────┘
    
    User: Click link dari email
           ↓
    [VALIDATE SIGNED URL] (middleware: 'signed')
    ├─ Invalid? → 403 Forbidden
    └─ Valid? → Continue
           ↓
    ┌─────────────────────────────────────┐  ┌──────────────────────────────┐
    │ SCENARIO A: Pendaftaran EXISTS      │  │ SCENARIO B: Pendaftaran NONE  │
    └─────────────────────────────────────┘  └──────────────────────────────┘
             │                                           │
             │ Route:                                    │ Route:
             │ /pendaftaran-sertifikasi/{id}/detail      │ /pendaftaran/lanjut/{id}
             ↓                                           ↓
             │                                           │
        [SHOW DETAIL]                              [DB TRANSACTION]
        └─ Nomor pendaftaran                       ├─ LOCK pra_pendaftaran
           Status                                  ├─ Double-check: exists?
           Skema (if any)                          │  ├─ YES → Redirect (idempotent)
           CTA: Login/Register                     │  └─ NO  → CREATE 1x
                                                   └─ COMMIT
                                                           ↓
                                                   Redirect: /pendaftaran-sertifikasi/{id}/detail


┌─────────────────────────────────────────────────────────────────────────┐
│ 4️⃣  USER CONTINUES (LOGIN REQUIRED)                                      │
└─────────────────────────────────────────────────────────────────────────┘
    
    User: Login dengan email yang sama
           ↓
    Route: /pendaftaran-sertifikasi (auth)
           ↓
    User dapat:
    ├─ Pilih skema kompetensi
    ├─ Upload dokumen persyaratan
    ├─ Pilih jadwal asesmen
    └─ Track status asesmen


╔══════════════════════════════════════════════════════════════════════════╗
║                          IDEMPOTENCY GUARANTEES                          ║
╚══════════════════════════════════════════════════════════════════════════╝

✅ 1 Email = 1 Pra-Pendaftaran DITERIMA (max)
   └─ Hard validation di form /daftar

✅ 1 Pra-Pendaftaran = 1 Pendaftaran Sertifikasi (max)
   └─ Check + DB Lock di ResumePendaftaranController

✅ Double click email link → Same result (no duplicate)
   └─ Pessimistic lock + double-check pattern

✅ Concurrent requests → Only 1 record created
   └─ DB lockForUpdate() prevents race condition

✅ Email resend → Same URL, same pendaftaran
   └─ Smart link logic di Mailable


╔══════════════════════════════════════════════════════════════════════════╗
║                            SECURITY FEATURES                             ║
╚══════════════════════════════════════════════════════════════════════════╝

🔐 Signed URL (Laravel temporarySignedRoute)
   ├─ URL tidak bisa ditebak (HMAC signature)
   ├─ URL tidak bisa dimodifikasi
   ├─ URL expire setelah 30 hari
   └─ URL tied to application key

🔐 Validation Middleware (signed)
   ├─ Automatic validation di route
   └─ 403 jika invalid/expired

🔐 Database Locks (Pessimistic Locking)
   ├─ lockForUpdate() prevents race condition
   └─ Transaction rollback jika conflict
